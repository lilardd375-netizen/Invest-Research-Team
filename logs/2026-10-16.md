## b) 当前架构

图从 planner 到 finalize 是一条带返工回环的流水线：planner 产出大纲 → 四个分析师
（财务 / 行业 / 舆情 / 技术面）**并行**消费风险质询与数据源 → 风控复核给出
severity 与逐条质询 → 条件路由决定返工还是成稿；返工只把质询按 target_agent 分发回
分析师（`revise` 仍是占位节点，只做分发与轮次+1），成稿节点今日起由真实 LLM 合成报告、
失败时规则式兜底，最后渲染成 Markdown 落盘。四个分析师与风控、planner、finalize 都是
真实 LLM；`revise` 与「未注入依赖时的占位节点」是仅剩的占位实现。数据源任一失败时该分析师
降级为 `unavailable` 并把原因写进 `analyst_errors`，流程照走不编造。

```
   query
     │
     ▼
 [planner]★ ──outline──► ┌──────────────────────────────────────────────┐
                         │  [financial]★ [industry]★ [sentiment]★ [technical]★ │  ← 并行 fan-out
                         │  各自消费 pending_challenges + 自己的数据源     │
                         └──────────────────────┬───────────────────────┘
                                                ▼  fan-in
                                        [risk_review]★
                                     severity / challenges
                                                │
                                    route_after_review（纯函数）
                    high 且 revision_round<2 且未卡住 ──► [revise]☆ ──► 回到四分析师 ↺
                                                │
                                    否则/撞上限/卡住保险丝 ──► [finalize]★ ──► END
                                                        （失败→规则式组装）
                                                              │
                                                     render_report → reports/*.md
```
