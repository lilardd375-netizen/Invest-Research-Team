## b) 当前架构

主编出大纲后 **四个分析师并行**（财务 / 行业 / 舆情 / 技术面），四份分析 fan-in 到风控；
风控判 `high` 时把质询按 `target_agent` 分发、回到四个分析师重跑（无待办者幂等跳过），
最多返工 2 轮，随后成稿。全部分析师共用同一套模板（只依据给定数据、`key_points` 标注
`data_source`、缺失写进 `concerns`/`assumptions`、禁止编造），降级一律写
`unavailable` + `*_error`，绝不编造。

```
                ┌────────────────────────────────────────────┐
   query ─────► │ planner  ★真实 LLM                          │  大纲 4-6 板块
                └───────────────┬────────────────────────────┘
                                │ fan-out（同一超级步）
      ┌───────────────┬─────────┴────────┬───────────────┐
      ▼               ▼                  ▼               ▼
 ★financial      ★industry          ★sentiment      ★technical
  akshare 财务     板块+同业 PE/PB     10 条新闻        120 日线统计
      └───────────────┴─────────┬────────┴───────────────┘
                                │ fan-in
                                ▼
                ┌────────────────────────────────────────────┐
                │ risk_review  ★真实 LLM                      │  severity + challenges
                └───────────────┬────────────────────────────┘
                                ▼  route_after_review（纯函数）
        high 且轮次<2 且未卡住 ──► ☆revise（按 target_agent 分发，占位逻辑：只分组+轮次+1）
                                │        │
                                └── ↺ ───┘  回到四分析师（无待办者幂等跳过）
                                │
                        否则 ──► ☆finalize（占位："stub report"）──► END
```

★ = 真实 LLM 节点（planner / financial / industry / sentiment / technical / risk_review）；
☆ = 占位节点（**revise 只做分组与轮次推进；finalize 仍是 `stub report`，第八步才真实化**）。

耗时归因（2026-10-15 真实冒烟阶段二 428.5s）：**服务端过载 × SDK 隐藏重试 × 16 次真实
调用**，非代码缺陷（planner 仅 6.2s；返工轮并行批 203s；无挂死、有 DONE 标记、无残留进程）。
client 的 `max_retries` 维持 SDK 默认，留观。

## c) 已知问题 / 技术债

1. **风控降级写出的 `severity="low"` 与真实评审结果在 state 中不可区分**：本次冒烟第 3 次
   复核就是降级（`risk_error` 非空），外部只看 `severity` 会误判成"风控认为风险低"。
   第八步报告合成必须依据 `risk_error`/`error_kind` 显式标注"本轮风控未生效"，
   不能让降级的 low 冒充结论。
2. **"只披露未修正"待复现确认**：风控第 2 轮逐条指出三家分析师只是承认局限、没有修正
   （口径不自洽未重算、单期数据仍外推、同业样本仍不可比）。**待明早错峰重跑确认是否复现**；
   若复现，分析师 prompt 需加"必须重算 / 给出修正后数值"的硬约束，而不是允许用
   `assumptions` 声明代替修正。
3. **push2his（日线）突发限流**：实测同一 300 日窗口第 1、2 次成功（0.9s / 196 行），第 3 次起
   连 30 日小窗口也 `RemoteDisconnected`，隔约 1 分钟新进程首次调用即恢复。已加
   1.5/3/6/12 秒递增退避（5 次尝试、总耐心约 23s），**本次仍用满 5 次共 38.5s 失败**
   → 技术面节点降级。冷却时间不稳定，退避上限仍可能兜不住；如需根治得换数据源或加缓存。
4. **Windows 中文路径 CA 坑**：`curl_cffi` 底层 libcurl 无法从含中文的路径加载 CAfile
   （`SSLError: curl: (77) ... CAfile:`），与证书内容无关——同一份 `cacert.pem` 放到 ASCII
   路径立刻恢复。已用 `utils.ensure_ascii_ca()` 在导入时把 CA 复制到 ASCII 目录并设置
   `CURL_CA_BUNDLE`/`REQUESTS_CA_BUNDLE`/`SSL_CERT_FILE`（`IR_SKIP_CA_BOOTSTRAP=1` 可跳过）。
   值得记住：任何在中文路径下用 libcurl 的项目都会踩。
5. **tool call 中断 × 分钟级真实冒烟**：真实冒烟要 6-8 分钟，交互式调用容易被中断而丢掉
   全过程。**对策已落地**：脚本写日志文件、每行带 `[HH:MM:SS +Ns]` 时间戳、结尾打
   `SMOKE STAGE1/2 DONE` 标记，另加逐节点进入/退出与每轮 severity 行；以后所有分钟级
   真实冒烟一律走这个模式。
6. **覆盖缺口**：估值 / 宏观 / 政策维度没有数据源（风控已被要求不因此判 high，但报告
   要显式披露）；标的自身估值（PE/PB/分位）目前四家都给不出。
7. **同业样本不可比**：industry 的同业只按 `stock_value_em` 返回顺序取前 3 只
   （`peers_note` 已自认非按市值排序），本次风控两轮都点名（含设备类公司与 30 亿市值小票）。
8. **样本量小**：舆情仅 10 条新闻、约 7 天窗口；财务仅一个报告期（2026-06），
   无 4-8 季度趋势 → 单期外推风险被风控反复点名。
9. **LLM 服务端过载**：`Service is too busy`（DeepSeek 侧）会以 `APIConnectionError` 出现，
   归类可重试 → 重试 1 次 → 仍失败降级。叠加 SDK 默认 `max_retries=2`，单节点最坏约
   6 次 HTTP 请求，耗时被放大到分钟级。`max_retries` 暂不动，留观。
10. **finalize 仍是占位**（`stub report`）：真正的问题不是缺模板，而是四份分析 + 风控
    质询 + 降级标记还没有合成器（第八步）。
